# P3 feedback result — partial-loss detection-to-quarantine measured on silicon

**Status:** updated 2026-08-30. The partial-loss path is now integrated and measured from the
switch timestamp on an attributed downstream gap event to the switch timestamp on the first exact
experiment packet observed on the backup. P3 remains partial because total-blackhole liveness and
audit/probation restoration have not run as one silicon lifecycle.

## What is actually known

A C-W4 discontinuity is observed downstream, while P2's health gate changes the spray choice at the
source. The required path is therefore:

```text
downstream C-W4 gap -> attributed event transport -> source selector -> exact health-gate update
```

The implemented path is:

```text
gap event -> exact parser -> frozen pooled inference -> four-row BFRT batch -> backup packet
```

Across 20/20 valid hardened Tofino trials, event-to-first-rerouted-packet latency was
**4.998 ms median**, 3.998–5.499 ms range, and 18/20 trials were at or below 4.999 ms. The gate RPC
was 3.582 ms median and its switch-agent BFRT batch was 2.755 ms median. A demand-targeted four-cell
census was 7.7 ms median, versus about 250 ms for the old 1,024-cell sweep; no census error occurred.
Every trial had one gap, one quarantine decision, one strict batch write, and at least 160,504
pooled baseline packets
against the frozen 100,000-packet warm-up.

The backup attention register was temporarily raised to 255/256 sampling probability so `t1`
measured the first rerouted packet rather than the random wait until an ordinary low-rate telemetry
sample. This is measurement instrumentation: it changes mirror overhead, not detection, inference,
gate programming, or forwarding. The ordinary sampler produced a correct but non-causal 165.995 ms
proof delay in an earlier run, after the gate was already live.

The **97.4 us** result in `p4/reports/h7-timing-F6.md` is an in-pipeline reaction to locally visible
congestion. It does not transport a downstream loss event upstream. The repository's loss-specific
F1 report instead records a 10.115 ms host observation path and explicitly says no in-switch loss
path was built.

Full per-run values, raw-log hashes, harness corrections, and the independent selective-isolation
check are in `artifacts/HW-CLOSED-LOOP.md` and
`artifacts/P3-HW-CLOSED-LOOP-HARDENED-2026-08-30.csv`.

## Controller state that now exists

`controller/sublink_feedback.py` contains a testable decision core and a narrow BFRT writer:

- one downstream event names `(directed vlink, context, epoch)`;
- the frozen pooled inference layer decides quarantine;
- one link-context decision expands into all exact P2 keys sharing that directed link;
- duplicate decisions coalesce per sublink epoch;
- earlier-epoch events are rejected;
- restoration requires positive probation/audit observations—silence after rerouting is not
  treated as evidence of health;
- BFRT add/modify/delete uses the real P2 fields and does not mask non-BFRT programming failures.

The running hardware controller now parses the attributed mirror into `GapEvent`, consumes one
batched demand census, applies the frozen decision layer, and programs all affected gate keys in
one request. A separate silicon isolation check sent 2,000 packets per context: the bad primary
sublink gained zero, its backup gained 2,000, and all three healthy primary contexts gained 2,000
(one also saw one background packet). No integrated probation path has restored a link on silicon.

## Structural observability limit

Ordinary C-W4 exposes a loss only when a later packet in the **same context sequence** survives and
arrives with a discontinuity. A context that becomes a complete black hole has no later survivor,
so it produces no C-W4 gap. This directly affects the motivating “all packets above 1 KB disappear”
case. P4 must not replay that case as though P3 had detected it.

P3 can pass only after one of these claim boundaries is chosen and implemented:

1. restrict the detector claim to partial conditional loss with same-context survivors, and price a
   separate liveness/audit mechanism for total black holes; or
2. add a cross-context/liveness witness and prove its encoding, wrap/reorder behavior, false alarms,
   compiler fit, and residual blind spots.

## Remaining P3 gate

Before P4 can support a completed-lifecycle and application paper claim, the repository still needs:

- an integrated probation/audit/receipt/removal route for restoration;
- replay of persistent, repaired, flapping, reordering, wrap, partial-loss, selective-blackhole,
  and all-context-blackhole cases through the implemented epoch state machine;
- matched false-alarm/safety operating points with confidence intervals.

Until then, P3 is **PARTIAL**: detection-to-quarantine is a measured result; liveness and
restoration remain open.
